# 펍냥이 지속 개선 루프 프롬프트

아래 블록을 저장소 루트에서 실행하는 코딩 에이전트에 전달하세요. 기존
`npm run agent`의 자동 주입 프롬프트가 아니라 **바깥쪽 에이전트용**입니다.
실제 무한 실행에는 호스트의 반복 실행/대기 기능과 인증·서명 권한이 필요합니다.
이 파일을 만들거나 읽는 것만으로 루프가 시작되지는 않습니다.

```text
이 저장소의 AGENTS.md와
.agents/skills/pubnyan-improvement-loop/SKILL.md를 읽고 지시된 reference를 적용하세요.
목표는 펍냥이의 귀여움·감정 전달·렌더링·페이지 연결·검증 속도를 지속 개선하는 것입니다.

이번 실행은 반복 모드입니다. 내가 중지하거나 호스트 예산이 소진될 때까지
증거가 있는 개선을 한 사이클씩 수행하세요. 무의미한 변경은 만들지 마세요.
새 실행에서는 data/improvement-loop/state.json을 실제 로컬 Git 상태와 대조해 이어가세요.

허용 범위:
- motion, rig 원본 매핑과 정식 생성물, 테스트, 시각 검토 도구, landing/Storybook 연결.
- 검증 성능 개선은 측정부터 시작하며 packages/* 수정은 명시된 backlog 범위 안에서만 수행.
- 저장소의 실제 git_commit 도구를 통한 로컬 커밋과 검증된 후보의 로컬 main
  fast-forward 병합까지만 매 사이클 허용합니다.
- 어떤 브랜치·태그도 푸시하지 마세요. 원격 PR 생성, workflow dispatch, 다른 API를
  통한 배포도 하지 마세요. 위임한 worker와 helper에도 같은 제한을 적용하세요.
- 과거의 푸시·배포 승인이나 체크포인트는 재사용하지 마세요. 공개 반영은 이 루프
  밖에서 내가 별도로 새로 요청할 때만 수행합니다.
- 이 승인은 서명·인증 우회, force push, 직접 git commit, 보호 브랜치 우회,
  임의 rollback, 다른 사용자 변경 포함, 유료 서비스 추가 권한이 아닙니다.

매 사이클:
1. 전체/순환 시각 감사와 이전 기록에서 가장 가치 있는 문제 하나를 선정합니다.
2. 눈 감기 전·중간·완전히 감김·다시 뜨는 프레임을 실제 이미지로 확인합니다.
   눈동자 clipping, 과한 흰자, 찌그러짐, 깜빡임, 감정 전달과 타이밍을 개선합니다.
3. 새 액션은 갤러리와 Storybook뿐 아니라 필요한 Stage/Machine 입력과 전환까지 연결합니다.
   gallery-only 또는 hero 제외는 명시된 수용 기준으로 남깁니다.
4. 편집 중에는 관련 테스트로 빠르게 반복하고, 최종 후보는 전체 검증을 통과시킵니다.
   성능 작업은 동일 workload의 전후 반복 측정으로 입증합니다. 검증 범위는 줄이지 않습니다.
5. 시각 검토와 페이지 검증 후 실제 커밋 도구를 사용합니다. 런타임이 제공하는 정확한
   모델 ID의 attribution trailer와 기존 서명을 지킵니다. 캐시를 직접 조작하지 않습니다.
6. 로컬 페이지에서 갤러리·Storybook·Stage 동작을 확인하고 로컬 main에 fast-forward
   병합합니다. 원격보다 앞서 있는 상태는 정상이며 푸시하지 않습니다.
7. 변경 이유, 전후 이미지, 테스트, 시간 측정, 로컬 commit SHA, 로컬 페이지 검증 결과와
   다음 작업을 체크포인트에 남기고 다음 사이클로 넘어갑니다.
   publication은 not_requested로 기록하고, 배포되지 않았다는 이유로 대기하지 마세요.
   기존 release_pending/live_verify 기록은 로컬 상태를 재확인해 전환하고 배포를 재개하지 마세요.

서명/필수 도구 인증 실패, 소유권 충돌, merge divergence, 검증 도구 부재, 로컬 페이지 검증 실패는
작업을 보존하고 원인을 보고한 뒤 중단하세요. 개선 시도가 3회 연속 실패해도 중단하세요.
유익한 개선점이 없으면 기본 5분 대기하되 호스트 대기/스케줄러를 사용하세요.
백그라운드 지속 실행을 지원하지 않는 환경에서는 체크포인트를 남기고 그 한계를 알리세요.
이번 승인은 다른 세션의 체크포인트 파일만으로 자동 승계하지 마세요.
```

처음에는 위 블록의 “반복 모드” 문장을 “한 사이클만 수행하고 결과를 보고하세요”로
바꿔 시험 운용할 수 있습니다. 스킬은 `.agents/skills/`에 보관하므로 프로젝트 스킬로
발견할 수 있습니다. 새 세션에서 `$pubnyan-improvement-loop`로 호출하거나 위 경로로
직접 읽을 수 있습니다. 전역 설치나 기존 worker 코드 변경은 하지 않습니다.

현재 사전 조건: Planner/loop의 bookkeeping 커밋 경로는 런타임의 attribution 요구와
충돌할 수 있습니다. 스킬의 preflight에서 이를 확인하고, 충돌하면 해당 경로를 실행하지
않습니다. 완전 무인 운용 전에 인증·서명과 이 경로의 호환성을 해결해야 합니다.
